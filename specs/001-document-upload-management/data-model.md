# Data Model: Document Upload and Management

## Document

Represents a stored work document and its searchable metadata.

Fields:

- `DocumentId`: integer primary key.
- `Title`: required, searchable title.
- `Description`: optional searchable description.
- `Category`: required text from the six approved categories.
- `Tags`: optional searchable user-provided tags.
- `OriginalFileName`: display-only source name; never used as a storage path.
- `StorageKey`: required relative key generated by the application.
- `FileSize`: required byte count, maximum 25 MB.
- `FileType`: required MIME type, maximum 255 characters.
- `UploadedByUserId`: required user relationship.
- `ProjectId`: optional project relationship.
- `UploadedDate`: required UTC timestamp.
- `UpdatedDate`: UTC timestamp for metadata/file replacement changes.
- `ScanStatus`: required state such as PendingScan, Clean, Rejected, or ScanUnavailable.
- `ScanAttempt`: integer attempt number used for idempotent queue processing.
- `ScanCompletedDate`: nullable UTC timestamp.
- `ScanFailureReason`: nullable non-sensitive operational reason for rejected/unavailable states.

Relationships:

- Many documents belong to one uploader.
- Many documents may belong to one project.
- Documents may have many shares, activities, and task associations.

Validation:

- Title and category are required.
- File size is greater than zero and no more than 25 MB.
- File type and extension must be on the supported allowlist.
- Storage key is generated from trusted IDs and a GUID; user input cannot control directories.
- A document is not listable, previewable, downloadable, shareable, or attachable while `ScanStatus` is not `Clean`.
- A repeated queue message for an already finalized scan is a no-op.

## DocumentShare

Represents a document grant to a user or team.

Fields:

- `DocumentShareId`: integer primary key.
- `DocumentId`: required document relationship.
- `SharedWithUserId`: optional user recipient.
- `SharedWithDepartment`: optional team/department recipient.
- `SharedByUserId`: required actor relationship.
- `CreatedDate`: required UTC timestamp.

Validation:

- At least one recipient target is required.
- A recipient must be active and within the sharer’s authority.
- Duplicate active grants for the same document and target are not created.

## DocumentActivity

Immutable audit record for document actions.

Fields:

- `DocumentActivityId`: integer primary key.
- `DocumentId`: required document relationship when the document still exists; retain a safe document reference value if deletion removes the relationship.
- `UserId`: required actor.
- `Action`: required text such as Upload, Download, Delete, or Share.
- `CreatedDate`: required UTC timestamp.

Validation:

- Every successful upload, download, deletion, and share writes one activity record.
- Activity records are readable through administrator-only report operations.

## DocumentTaskAssociation

Join entity connecting a document to a task and its project.

Fields:

- `DocumentTaskAssociationId`: integer primary key.
- `DocumentId`: required document relationship.
- `TaskId`: required task relationship.
- `CreatedByUserId`: required actor.
- `CreatedDate`: required UTC timestamp.

Validation:

- The task’s project must match the document project when both are present.
- The actor must be authorized to access the task and project.

## Existing Entity Changes

- Add document collections to `Project` and `TaskItem` only where they improve query composition; avoid eager-loading large files or activity histories.
- Extend `NotificationType` with document-sharing and project-document values.
- Extend `DashboardSummary` with the document count; retrieve the five recent documents through the document service.

## State Transitions

1. Selected: file exists only in the upload request.
2. Quarantined: validated content is stored under a generated quarantine key and metadata is committed as `PendingScan`.
3. Scan queued: a queue message identifies the document, quarantine key, and scan attempt.
4. Clean: the worker completes scanning, promotes content to its available key, and the document becomes accessible.
5. Rejected or unavailable: the worker denies access and records a safe failure state; retryable failures return to the queue, then move to poison handling after the retry limit.
6. Shared: one or more valid recipient grants exist only after the document is clean.
7. Replaced: a replacement enters quarantine and follows the same scan lifecycle; no version history is retained.
8. Deleted: metadata, shares, associations, and physical content are permanently removed after authorization and confirmation; the activity record remains available for audit.
